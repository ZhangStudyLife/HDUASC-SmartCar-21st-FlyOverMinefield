# Mode1/2/4/5 空车分离调试日志设计

## 目标

统一飞机端和车端在 Mode1、Mode2、Mode4、Mode5 下的调试字段位置，但保持两端日志相互独立：

- 飞机 WiFi 只发送飞机控制量和飞机下发指令。
- 车端 WiFi 只发送车端收到的指令、转向状态机、编码器、速度环和电机量。
- 飞机不通过自己的 WiFi 重复转发车端日志。
- 两端通过飞机时间戳和各自 JustFloat 自动本机时间戳离线同步。
- 能由已发送数据稳定推算的量不占用实时日志槽位。

## 采样与同步

- 飞机日志保持 200 Hz，固定发送 30 个用户 `float`。
- 车端日志跟随 100 Hz 控制周期，固定发送 42 个用户 `float`。
- 两端 JustFloat 保持现有行为，在用户数据前自动添加本机 `tick_1000us_cnt` 时间戳。
- 飞机飞行关键 AirComm 帧新增 `air_tick_ms`。
- 车端保存最近收到的 `air_tick_ms`，并放入车端日志 C9。
- 后处理使用车端自动时间戳与 C9 建立车端时钟到飞机时钟的映射，再与飞机日志自动时间戳对齐。

## 飞机日志布局

飞机日志在 Mode1、Mode2、Mode4、Mode5 下固定为相同的 30 个用户槽位。

| 槽位 | 内容 |
|---|---|
| A1 | 当前飞行 Mode |
| A2 | 当前 Mode 的 100 Hz 控制序号 |
| A3 | 飞机下发 CRSF ch0 |
| A4 | 飞机下发 CRSF ch1 |
| A5 | 飞机下发 plan_valid |
| A6 | 飞机下发 plan_strafe，m/s |
| A7 | 飞机下发 plan_forward，m/s |
| A8-A10 | 飞机实际 Roll、Pitch、Yaw，deg |
| A11-A13 | 飞机目标 Roll、Pitch、Yaw，deg |
| A14-A16 | 飞机实际 Roll、Pitch、Yaw 角速度，deg/s |
| A17-A19 | 飞机目标 Roll、Pitch、Yaw 角速度，deg/s |
| A20-A21 | 当前 Mode 图像 X/Y 误差 |
| A22-A23 | 当前 Mode 图像 X/Y 控制器 P 项 |
| A24-A25 | 当前 Mode 图像 X/Y 控制器 D 项 |
| A26-A27 | 当前 Mode 滤波后的车速误差 X/Y，m/s |
| A28-A29 | 当前 Mode 最终 Roll/Pitch 加速度前馈，deg |
| A30 | 当前 Mode 使用的车数据间隔，ms |

飞机端使用一次 Mode 分支选择 Mode1、Mode2、Mode4 或 Mode5 的专属变量填入 A2、A20-A30。公共字段 A3-A19 不按 Mode 改变位置。

## 车端日志布局

车端日志在 Mode1、Mode2、Mode4、Mode5 下固定为相同的 42 个用户槽位。

| 槽位 | 内容 |
|---|---|
| C1 | 当前车端 Mode |
| C2 | 车端控制使能 |
| C3 | 车端 100 Hz 控制周期序号 |
| C4 | 车端收到的 CRSF ch0 |
| C5 | 车端收到的 CRSF ch1 |
| C6 | 车端收到的 plan_valid |
| C7 | 车端收到的 plan_strafe，m/s |
| C8 | 车端收到的 plan_forward，m/s |
| C9 | 最近收到的飞机 air_tick_ms |
| C10-C11 | 车 yaw 反馈、目标，deg |
| C12 | 大角度转向状态 |
| C13 | 大角度转向重新触发锁 |
| C14 | 常规停车制动状态 |
| C15-C16 | 基础速度命令、基础速度目标，编码器 count/10ms |
| C17-C18 | 左右编码器原始反馈，count/10ms |
| C19-C20 | 左右编码器滤波反馈，count/10ms |
| C21-C22 | 左右轮速度目标，count/10ms |
| C23-C24 | 左右电机最终 PWM |
| C25-C26 | yaw 角度环 P、D 项，deg/s |
| C27 | gyroz 目标，deg/s |
| C28 | gyroz 滤波前反馈，deg/s |
| C29 | gyroz 控制使用的滤波后反馈，deg/s |
| C30-C32 | gyroz 环 P、I、FF 项 |
| C33-C37 | 左轮速度环 P、I、D、静态 FF、制动 FF |
| C38-C42 | 右轮速度环 P、I、D、静态 FF、制动 FF |

Mode4 和 Mode5 的诊断获取函数补齐与 Mode1/2 相同的 yaw、gyroz、左右速度环分项。日志不得改变 PID、状态机或电机控制行为。

## 不发送的可推算量

以下量不占用实时日志槽位：

- yaw 误差：由 yaw 目标和反馈做角度环绕差得到。
- yaw 与 gyroz PID 总输出：由分项、限幅和最终轮目标离线分析。
- 实际车速：由左右编码器滤波反馈和现有换算比例计算。
- 大转向方向、锁存目标和周期计数：由 yaw 目标/反馈、状态和时间序列重建。
- 图像误差变化率：由相邻图像误差和时间戳差分得到。
- 图像控制器总输出：由 P、D 项求和并按控制限幅重建。
- 滤波前车速误差、车体系加速度、坐标旋转后加速度和向心加速度：由同步后的空车数据与参数离线计算。
- 原始 Roll/Pitch 修正量和空车 yaw 差：由已记录目标、前馈和同步 yaw 数据计算。

## 代码范围

飞机端：

- 扩展飞行关键 AirComm 帧，加入 `air_tick_ms`。
- 将现有 Mode1/2 WiFi 调试函数改为 Mode1/2/4/5 共用的 30 槽日志。
- 删除飞机 WiFi 日志中的车端反馈量，不改变飞控控制逻辑。

车端：

- 解析并保存飞行关键帧中的 `air_tick_ms`。
- 将现有 Mode1/2 车端日志改为 Mode1/2/4/5 共用的 42 槽日志。
- 补齐 Mode4/5 的 `car_drive_diag_t` 字段。
- 保持车到飞机的现有 11 槽运行数据及其控制用途不变；本次不把车端详细日志转发给飞机。

## 验证标准

1. 飞机端只有 Mode1、Mode2、Mode4、Mode5 飞行时发送固定 30 槽日志。
2. 车端只有 Mode1、Mode2、Mode4、Mode5 控制运行时发送固定 42 槽日志。
3. 四个 Mode 切换前后，每个索引的语义和单位不变。
4. Mode4/5 的 yaw、gyroz、左右速度环分项不再为未填写的零值。
5. 飞机日志不包含车端编码器、车端 PID 或车端状态机字段。
6. 车端 C9 随飞机 `air_tick_ms` 更新，可与两端自动时间戳一起用于离线同步。
7. 飞机与车端工程通过现有编译或至少完成工程级语法检查；日志数组长度均不超过 JustFloat 上限。
