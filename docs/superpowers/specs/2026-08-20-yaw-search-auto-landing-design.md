# Yaw 搜索与自动降落设计

## 目标

修正 `yawmode == 2` 时航向搜索反复启停、目标不规整和 Mode4 自动降落等待过久的问题。

最终方案统一使用 `CarPlan_3_GetResult()` 返回的 `plan_result.valid` 判断是否得到可信目标速度，不再使用原始信标可见状态控制 yaw 搜索或自动降落。搜索目标始终是 45 度的整数倍，搜索时 yaw 角度环 Kp 为默认值的两倍，不增加 yawrate 限幅。自动降落恢复提交 `0e9c94d` 的独立计时逻辑，不再等待实际旋转达到 360 度。

该选择意味着 `plan_result.valid` 依赖车灯和信标共同形成有效规划结果。当信标存在但车灯或规划结果无效时，系统仍按无目标处理。此行为是本方案的明确约束。

## 日志结论

`新旋转日志.csv` 中，飞行期间原始信标状态频繁抖动：可见区间中位数约 110 ms，82 个区间不超过 200 ms。旧逻辑每次看到原始信标都会停止搜索并清零实际旋转进度，下一次丢失又重新选择搜索方向，因此 yaw 目标和 Kp 反复切换。

日志中最后一次连续 100 ms 的有效规划结果结束于约 156.615 s。之后虽然存在多次最长约 310 ms 的原始信标检测，`plan_result.valid` 始终无效。旧逻辑因此延迟到 187.180 s 才触发降落。

## 有效目标状态

`plan_result.valid` 是本算法唯一的目标有效性输入。

Mode4 本次会话首次进入 yawmode=2 时，必须先出现一次有效且非零的车目标速度。此前 yaw 目标保持当前飞机 yaw，不启动搜索；离开 Mode4、关闭车开关或飞控复位都会清除这个“已下发目标速度”标志。

- `plan_result.valid == 1` 的第一帧出现时，暂停产生新的 45 度搜索目标，但保持当前目标不变。
- 连续有效达到 100 ms 时，确认目标有效，恢复默认 yaw 角度环 Kp，并清零无目标计时和本轮实际旋转进度。
- 连续有效不足 100 ms 又变为无效时，不确认重捕获，不清零搜索方向和实际旋转进度，从当前搜索档位继续。
- 连续无效达到 150 ms 时，进入或恢复旋转搜索。

例如当前搜索目标为 90 度，飞机旋转到 70 度时 `plan_result.valid` 变为 1，目标仍保持 90 度。飞机继续完成 90 度目标，但暂停生成下一个 135 度目标。连续有效达到 100 ms 后恢复软 Kp；若不足 100 ms 又失效，则继续生成后续 45 度档位。

## 搜索目标

进入搜索时，根据线缆累计扭转选择减小扭转的搜索方向，并在本轮搜索中保持该方向。

首个目标是搜索方向上的下一个绝对 45 度网格点：

- 当前 yaw 为 45 度、正方向搜索时，首个目标为 90 度。
- 当前 yaw 为 70 度、正方向搜索时，首个目标为 90 度。
- 当前 yaw 为 92 度、负方向搜索时，首个目标为 90 度。
- 当前 yaw 已经位于网格点时，首个目标必须是搜索方向上的下一个网格点，不能停留在原网格点。

此后每累计 750 ms 的有效搜索时间，沿同一方向增加 45 度目标。`plan_result.valid == 1` 但尚未连续满 100 ms 时暂停 750 ms 计时；结果再次无效后从暂停点继续。

传给现有角度控制器的目标可以包角到 `[-180, 180]`，但包角前后的目标都必须保持为 45 度的整数倍。`yawmode == 2` 不再使用信标像素偏差生成非 45 度倍数的 yaw 目标。

## 动态 Kp

- 确认目标有效、进入自动降落状态或退出搜索控制时，使用 `g_fc_params.yaw_angle_kp`。
- 连续无效达到 150 ms 并开始搜索后，使用 `2.0f * g_fc_params.yaw_angle_kp`。
- 不对 yawrate 目标增加任何限幅，保留现有内外环控制输出范围。
- 搜索中连续有效达到 100 ms 后立即恢复默认 Kp，但保持当前 45 度目标不变。

## 实际旋转进度

每次航向更新使用飞机相邻两次实际 yaw 的 `[-180, 180]` 包角差，按本轮固定搜索方向累计：

```text
search_rotation_deg += search_direction * aircraft_yaw_delta_deg
```

反方向运动减少进度，进度下限为 0 度。短于 100 ms 的有效规划结果不清零进度，避免短脉冲伪造新的搜索轮次。

实际旋转达到 360 度后不停止搜索，也不恢复软 Kp。飞机继续沿原方向每 750 ms 生成新的 45 度目标，直到自动降落触发或确认目标连续有效 100 ms。实际旋转进度保留为搜索调试信息，不参与降落判定。

## 自动降落

保留 Mode4、飞行状态、`yawmode == 2`、`CRSF_STD[4] == 1` 和现有 5 秒前置等待条件。

自动降落独立读取 `plan_result.valid`，完全恢复提交 `0e9c94d` 的判定：

- `plan_result.valid == 0` 时累计无目标时间。
- `plan_result.valid == 1` 但连续不足 200 ms 时，无目标时间仍然累计。
- 连续有效达到 200 ms 时才清零无目标时间并返回。
- 无目标时间达到 5 秒时直接请求降落，不检查当前搜索旋转角度。

保留触发锁存：请求降落后不再重复判断，直到状态回到 `STANDBY` 或 `INIT` 才清空。若进入条件中任一项失效，前置等待、无目标计时和连续有效计时全部清零。

`CRSF_STD[4] != 1` 时禁止搜索和自动降落，yaw 目标保持 0 度。

## 回放预期

对 `新旋转日志.csv` 使用上述状态条件回放：

- 整趟日志首次满足入口约在 20.615 s；由于之后 10 秒内没有有效规划结果，恢复旧逻辑后会在约 30.615 s 触发降落。
- 本次日志第一次非零有效目标速度约在 33.530 s；新增前置门槛使其之前不产生搜索旋转。
- 该目标随后丢失并连续无效约150 ms后，最早约在 38.450 s 进入搜索。
- 约 156.770 s 连续无效达到 150 ms 并开始搜索。
- 最后一次连续 200 ms 的有效规划结果约在 156.615 s 结束。
- 若只隔离回放最后一次丢失目标，156.615 s 后没有新的 `plan_result.valid` 有效脉冲，无目标计时约在 161.615 s 达到 5 秒并直接触发降落。
- 旧日志直到 187.180 s 才触发，是因为当时的复杂逻辑会被原始信标状态和实际旋转 360 度门槛阻塞。

回放只能验证状态机和目标序列，无法精确预测修改控制指令后的真实机体响应。实机日志必须继续记录实际 yaw、yawrate、目标 yaw、Kp、`plan_result.valid`、搜索方向、实际旋转进度和自动降落条件。

## 验证标准

1. `yawmode == 2` 的所有 yaw 目标均为 45 度的整数倍。
2. 连续无效不足 150 ms 时不开始新的搜索旋转。
3. 搜索途中规划结果变为有效时保持当前目标，不锁定飞机当时的实际 yaw。
4. 连续有效不足 100 ms 时不清零搜索方向和实际旋转进度。
5. 连续有效达到 100 ms 后恢复默认 Kp并清零搜索历史；自动降落无目标计时仍要求连续有效 200 ms 才清零。
6. 搜索时 Kp 为默认值的两倍，且没有新增 yawrate 限幅。
7. 自动降落中，连续有效不足 200 ms 时无目标计时继续增长。
8. 无目标计时达到 5 秒时直接触发降落，与实际旋转进度无关。
9. `CRSF_STD[4] != 1` 时禁止搜索和自动降落，yaw 目标为 0 度。
